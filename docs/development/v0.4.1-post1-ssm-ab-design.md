# v0.4.1.post1 SSM-on/off minimum reproducer design

Status: proposed for review; no A/B execution is authorized by this document.

## Purpose and scope

The archived diagnostics establish that the frozen s2 treatment reaches a
sampled RSS peak of 9,315,592 KiB despite zero SSM records, while the frozen
s3 positive control reaches 937,252 KiB with 38,921 raw SSM records. This is
evidence of an association, not proof of a SUMO memory leak or an internal
cause.

The next experiment isolates the SSM device as one candidate factor. It must
not be interpreted as a replacement for, or a reclassification of, the
v0.4.1 pilot resource-gate failure.

## Frozen common treatment

Both arms use the exact treatment represented by
`configs/v0.4.1/ssm_reproducer_s2.json`:

| Field | Frozen value |
| --- | --- |
| scenario / network | `scenario_2` / `net/scenario_2/loop.net.xml` |
| model / vehicle composition | CACC / `vehN=120`, `cav_count=120` |
| assignment seed / SUMO seed | `as00` / `ss102` |
| simulation end / warmup / step | 3600 s / 600 s / 0.1 s |
| SSM capture profile when enabled | TTC=5.0 s, DRAC=3.0 m/s², range=50 m, extratime=5 s, trajectories=false |
| FCD | 1 s, maximum leader distance 4000 m |
| other outputs | route, additional, detectors, edgeData, lane-change, vehroute, FCD, stdout, stderr, RSS |

The frozen source case remains unchanged. The A/B descriptor records its
canonical frozen-case SHA and the network SHA before either arm may start.

## Arms

| Arm | Device setting | Required equivalence |
| --- | --- | --- |
| A: SSM-on | Preserve the existing SSM command arguments and `ssm.xml` output. | All common-treatment fields and all non-SSM output options are byte-for-byte identical at command construction. |
| B: SSM-off | Do not instantiate or configure SUMO's SSM device; `ssm.xml` is intentionally absent. | The only command-level difference from A is removal of SSM-device activation/configuration and its output target. |

The diagnostic state machine must make the B-arm absent SSM file an explicit,
expected condition—not a successful zero-event result and not a missing-evidence
failure. Its report must state `ssm_enabled=false` and `ssm_not_collected`.

## Evidence and acceptance

Each arm uses a new, non-reusable attempt under separate output roots. Before
SUMO starts, RUNNING must record the A/B descriptor SHA, arm ID, git commit and
dirty state, and all frozen input SHAs. Terminal state retains the existing
evidence inventory, with the intentional SSM-off omission separately named.

The comparison report must bind each terminal status, RSS JSONL SHA, peak RSS,
wall time, return code, FCD SHA, route SHA, and (for A only) SSM SHA/event
counts. It must report both absolute and ratio differences without declaring a
leak or internal SUMO cause.

No arm may start until the implementation and its state/missing-file regression
tests have an independent commit and Reviewer approval. Run A and B serially;
do not run any other memory-intensive process concurrently. If either arm is
TIMEOUT, FAILED, INTERRUPTED, OOM-terminated, or evidence-incomplete, pause
without retrying or changing parameters.

## Interpretation decision

If SSM-off materially suppresses the RSS growth while all common-treatment
checks pass, prepare a SUMO upstream issue from the archived evidence and A/B
artifacts. If it does not, do not attribute the growth to SSM; next isolate FCD,
network topology, or other output devices in separately reviewed designs.
