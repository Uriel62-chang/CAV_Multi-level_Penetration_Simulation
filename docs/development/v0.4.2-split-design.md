## 二、研究问题与 estimand

### 2.1 主 factorial（SSM disabled）

- **研究问题**：在四场景（s0–s3）、IDM/CACC、CAV 渗透率与车辆数网格下，
  CAV 跟驰控制对**观测流量、排放强度、参考相对圈时差**的影响是否随路网结构改变？
- **主要 estimand**：
  - 流量：网格内最大观测流量（延续 post3 口径，不做真实容量峰值声明）；
  - 排放：**non-internal-edge CO₂ g / non-internal-edge veh-km**（parser 同时累计 all-edge 与 non-internal-edge，主口径用 non-internal 配对，与 v0.4.0 可比；全路网强度作为次要字段）；
  - 效率：相对模型专属自由流参考的圈时差（D-008 artifact）；
    - **delay 定义（2026-07-31 拍板）**：每个有效 lap 先按车辆类型减对应参考（HV lap → HV ref；CAV lap → CAV_IDM/CAV_CACC ref），再在 run 内汇总；废弃"全体平均圈时 − HV reference"（P0-8 闭合）。
- **明确不属于主 factorial**：TTC/DRAC 事件、SSM 内存成本。

### 2.2 Safety experiment（独立）

- **研究问题**：在**受控安全子网格**上，TTC/DRAC 事件率是否随场景、模型、渗透率、
  车辆数变化；事件与暴露量在**同一空间范围**（`withInternal=true`）配对。
- **主要 estimand**：`全路网 SSM 事件 / 全路网 veh-km`（空间配对后的事件率），
  以及事件数、极值、受影响车辆数。
- **明确不属于 safety experiment**：流量/排放/延误主结论（可与主 factorial 关联，但受 §3 约束）。

### 2.3 双实验公共约束（IN-1）

- 时间窗：`[600, 3600)`；warmup 必须同时为 detector 与 edgeData frequency 的整数倍（沿用 post3 门禁）。
- 基本处理变量：`(scenario, model, vehN, cav_count)`；requested/realized pCAV 均记录，分析以 realized 为准并保留 requested。
- 双 seed 的统计单位（IN-9/P1-2 闭合）：
  - `assignment_seed`（车辆类型排列）与 `sumo_seed`（SUMO 随机种子）是**两个独立活动维度**；
  - 实验单位 = `(assignment_seed, sumo_seed)` 组合，每格权重 = 组合数；
  - 聚合层级：先在 run 内计算比率，再对 `(assignment_seed, sumo_seed)` 组合等权汇总；
  - 端点规范化：`cav_count ∈ {0, vehN}` 时 `assignment_seed` 失活（排列不产生新信息），但 `sumo_seed` 仍为活动维度，端点 run 的 `sumo_seed` 重复照常保留；
  - 报告必须给出每格有效 n（= 活动组合数）与 `seed_scope` 说明，不得把端点 n 解释为独立随机重复。
- 统计口径：比率在 run 内计算，跨 seed 等权汇总；不解释为独立随机重复、不用于显著性检验。

## 三、两实验联合推断契约（IN-6，最实质风险）

### 3.1 共享 treatment 键与配对静态验收（P1-3 闭合）

两实验必须共享以下键以允许跨实验关联：

```text
(scenario, model, vehN, cav_count, assignment_seed, sumo_seed)
```

- 主 factorial 与 safety experiment 在共享键上的 treatment 参数（车辆组成、初始位置生成、seed 语义、时间窗）必须一致；
- 任一实验修改共享键上的参数，必须在设计文档中显式记录并重新对齐，禁止静默漂移。

**配对静态验收**（证明共享键下两实验的 run 可配对，不要求新增 SUMO 诊断）：

1. 冻结输入 SHA 一致：network、routes、additional、vehicle_type_map 的 SHA-256 在两实验中逐 run 相同；
2. 规范化 SUMO 命令一致：除 SSM 参数与输出路径外，非 SSM 命令逐参数相同（复用 A/B 的
   `normalized_non_ssm_command_equal` 断言模式）；
3. 验收通过 dry-run/哈希比较完成（§10 验收项 2/3），不运行 SUMO。

### 3.2 Safety 子集抽样规则（P1-1：占位 → 网格设计门禁）

- safety experiment 从主 factorial 的 treatment 空间中抽样子集；
- **确定性选点规则与完整 treatment/seed 集、预期 run 数不得以「例如…」占位形式留在本设计文档中**；
  由用户确认后写入网格设计附录（§9 流程）；
- 网格设计门禁未通过前，不得按本设计文档生成 safety 网格或关联两实验数据；
- 子集必须覆盖四个场景与两个模型的公共键，以保证跨实验关联在共享键上可行；
- 端点 treatment（cav=0 / cav=vehN）不额外抽样，但按 §2.3 保留 `sumo_seed` 活动维度。

### 3.3 口径对齐

- 时间窗：两实验统一 `[600, 3600)`；
- **SSM 事件窗口归属的操作化**（P1-4 闭合）：
  - 以 `minTTC@time`、`maxDRAC@time` **分别**判断 `600 <= t < 3600`（沿用 post3 的极值时间过滤，
    但补齐上界）；
  - 现有 `scripts/parsing/ssm.py:71/127/141/153` 只有 warmup 下界过滤，**没有 3600 上界参数或检查**，
    实现时必须新增上界，并处理 conflict 横跨窗口边界、TTC/DRAC 极值分处不同窗口的情形（§10 验收项 4）；
- 暴露量：safety experiment 必须使用 `withInternal=true` edgeData 的 veh-km 作为分母，事件分子与分母同一 edge 子集（修复 v0.4.0「全路网事件/普通 edge 里程」的空间错配）；
- 模型参数：两实验使用同一 SUMO 版本、同一 vType 参数集。显式化范围限于
  emissionClass（P0-9，仅 v0.4.2）；IDM/CACC 模型专属默认参数、SSM measures
  等仍依赖 SUMO 隐式默认/项目硬编码，尚未全部显式化（P1-4，见 experiment-issues §3）。

### 3.4 允许与禁止的跨实验关联

- **允许**：在共享键上并列报告「主 factorial 的流量/排放/效率」与「safety experiment 的事件率」，
  作为**同一 treatment 的不同维度观测**；描述性讨论趋势。
- **禁止**：
  - 把两实验的独立结果拼接为单条「流量—安全权衡」曲线或统一拟合；
  - 用 safety 子集的稀疏采样推断主 factorial 全网格的事件率；
  - 以「s2 未检测到事件」推断「s2 无安全冲突」；
  - 跨实验因果断言（主 factorial 未采集 SSM，无法在 run 内配对）。

## 五、Safety experiment 设计

### 5.1 estimand 定义

- 阈值：TTC/DRAC 阈值单一来源化（消除 `config.py` 双源，见工程遗留①）；capture 阈值 ≥ analysis 阈值包络（沿用阶段 2 §7.4 前置验证）；
- 空间范围：事件分子与 veh-km 分母同一 edge 子集（`withInternal=true`）；
- dedup/fragment：`_MIRROR_OVERLAP_RATIO`/`_FRAGMENT_MERGE_GAP_S` 参数化（工程遗留③），dedup 方法在分析时显式选择并记录（none/greedy/sorted_greedy）；
- 事件定义：TTC 冲突、DRAC 冲突、极值（minTTC/maxDRAC + provenance，D-006）。

### 5.2 独立轨迹验证边界

- SSM 事件可选用 FCD/TraCI 独立复现作为**可选验证**，但**不设为 v0.4.2 默认交付**；
- 若未独立复现，报告必须声明「TTC 事件尚未由独立 FCD/TraCI 方法复现」（保持 README Limitations 表述）。

### 5.3 内存约束

- Safety 网格按**普通资源规则**运行（§7）：记录 RSS、OOM 后降并发 resume、并发数按机器当前 available RAM 动态调节；
- 不做独立校准门禁、不预设硬性单进程预算；SSM 参数必须**显式固定**（TTC/DRAC/range），避免依赖 SUMO 隐式默认（v0.4.0 默认 8 项 measures 与 v0.4.1 显式 2 项 5.0 阈值的差异是历史 RSS 观测差异的来源）。

| R2 | A/B ssm_on | `ad95058` | on | s2 CACC 120 | 0/0/0 | 9,340,844 | 47.14 | 47 | 零事件，最坏 RSS 观测 |

**关键结论（IN-10）**：sampled peak RSS 不能由最终输出的 SSM 事件数单调预测。
R2/R3（零事件）≈ 8.9 GiB 远高于 R4（38,921 事件）≈ 0.9 GiB；但这是非受控跨场景对照，
不得推断「事件越多内存越低」。**当前已观测最大值 = R2 的 9,340,844 KiB**。

## 七、调度与失败恢复（IN-2 / IN-10）

1. **并发数动态调节**：按机器当前 available RAM 决定，OOM 时降并发后 resume（v0.4.0 已验证 74 次失败后串行恢复是正常操作）；
2. **OOM 处理**：OOM 终止的 run 标记为 OOM-terminated，降并发后 resume；
3. **timeout**：硬截止沿用现有轮询机制（D-004）；超时 run 暂停，不静默重试；
4. **resume**：沿用 run 目录 + 状态机 + 哈希完整性校验；拒绝复用被修改的输入/输出；
5. **证据保留**：失败、超时、OOM run 保留 attempt 状态与 RSS 采样，写入缺失/异常清单，不覆盖、不追认；
6. **safety 网格并发**：不与其他内存密集进程并行（沿用 A/B 串行纪律）。
